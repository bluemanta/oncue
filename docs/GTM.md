# OnCue单词 · 推广方案（GTM）

写于 2026-09-28，给 marketing 用。产品背景先读 `产品说明.md`。

**读之前先知道一件事**：产品上线一天，核心卖点（发音判断准不准）还没量过，也还没有任何真实用户用过。所以这份文件不是"马上开始大推"的方案，而是**分三波走、每波有明确开关条件**的方案。第一波只要 20 个人。跳过第一波直接做第二波的风险写在最后一节。

---

## 一、定位

### 一句话

**遇到不会读的英文单词，丢进来，读给它听——它告诉你读对了没有。**

### 电梯稿（30 秒版，给对外介绍用）

> 工作里天天写的英文词，一到开口就没底：preference 的重音在哪？procurement 怎么念？
> 查词典只能听一遍标准读音，听完你也不知道自己读得对不对。
> OnCue 把句子贴进去，一次给你意思、读音、例句，然后你按住麦克风读一遍，
> 它告诉你哪个音读偏了、重音放错在哪、怎么改。
> 不用报课、不用打卡、不用注册，打开就用。

### 一句话对比（用户最常问的三个"那不就是"）

| 用户会说 | 回答 |
| --- | --- |
| "那不就是词典吗？" | 词典告诉你标准读音是什么，OnCue 告诉你**你读得对不对**。多的是最后那一步。 |
| "那不就是流利说 / ELSA 吗？" | 那些要你进课程、按计划练。OnCue 没有课程——你遇到一个词，用十秒解决它，然后关掉。 |
| "那我直接问 AI 不行吗？" | 问 AI 能拿到解释，但它是"听个大概"，说不出你是 th 读成了 s 还是重音放错了。OnCue 用的是专门的发音评测，逐个音比对。 |

### 核心信息与三个支撑点

**核心信息：别人告诉你标准答案，我们告诉你你的答案对不对。**

支撑点一：**闭环在一次操作里。** 贴进去 → 出卡片 → 跟读 → 得到反馈，不切换工具、不来回对话。
支撑点二：**指到音，不是给个分。** 不是"78 分，继续努力"，而是"schedule 开头你读成了 /ʃ/，应该是 /sk/"。
支撑点三：**为职场词准备的。** 例句是职场和销售场景，义项里职场含义排在前面。procurement 给你的不是词源，是你在 RFP 里看到的那个意思。

## 二、人群与优先级

完整画像见 `产品说明.md`。推广上按这个顺序打：

| 优先级 | 人群 | 在哪里能找到他们 | 为什么这个顺序 |
| --- | --- | --- | --- |
| 1 | 外企 / 出海公司的销售、售前、BD | 行业微信群、脉脉、同事同学的二度人脉 | 痛点最准、场景和例句库完全对口、且大概率就在你和团队的人脉一跳之内 |
| 2 | 跨境电商、外贸业务员、出海创业者 | 出海和跨境的垂直社群、知识星球、即刻 | 要跟海外客户开口，需求更急；社群密集，一个群能触达几百同画像用户 |
| 3 | 产品、项目、咨询岗 | 即刻、小红书、脉脉 | 专业词密度高，都是"只写不说"的词 |
| 4 | 技术人员 | 技术社群、掘金、即刻 | 量大好触达，但对"读得准"的紧迫感偏低，放后面 |

**不要投的方向**：学生和 K12、家长、零基础学英语、雅思托福备考。理由见 `产品说明.md`，简单说就是他们要课程和成绩，产品一样都不给，投进去转化不了，还会带来一批用完就骂的评价。

## 三、话术禁区（重要，请先读这一节）

这版产品有几个地方**现在还不能这么说**。说过头了，第一批用户就是最后一批。

| 不能说 | 为什么 | 现在可以怎么说 |
| --- | --- | --- |
| "精准识别每一个发音错误" / 给出准确率数字 | 20 个常错词的实测还没做，准确率目前没有任何数据支撑 | "指出最主要的一处问题"——这也确实是产品的设计原则 |
| "AI 外教" / "私人口语老师" | 产品刻意不做课程、不做陪练，这么说会招来错的人群，而且细微口音差别本来就不如真人 | "开口前的最后一道检查" |
| "支持美音英音切换" | 界面上没有这个功能（腾讯云现有英文音色实听全是美音） | "美式发音" |
| "记录你的生词，帮你复习" | 没有数据库，关掉页面什么都不剩 | 暂时不提，或明确说"这版不留记录，用完即走" |
| "上传截图直接查" | 没做 | "手机识别文字后粘贴进来" |
| "免费无限使用" | 每次查词都在花钱（大模型 + 语音合成 + 评测），且目前没有任何用量限制 | 不提免费，也不承诺永久免费 |
| 任何"提分""达到 X 水平"的表述 | 产品不测水平、不追踪进度 | 不提 |

另外两条：

- **不要把链接直接发在微信里让人点开就用**，原因见第六节第 1 条（微信内置浏览器可能录不了音）。要配一句"点右上角，在浏览器里打开"。
- **不要说"我们不保存你的数据"**。录音确实不保存，但**粘贴的内容会发给第三方大模型处理**。这是两件事，不能混着说。

## 四、渠道与动作

按性价比排序。前三项基本不花钱，建议先只做前三项。

### 1. 定向邀请 20 个人（第一波，必做）

不是"推广"，是拿反馈。从你和团队的人脉里挑 20 个**符合核心画像**的人——外企销售、售前、做出海的朋友。一对一发，附一句话说明和一个具体例子（"你试试把 procurement 读一遍"）。

要的不是"挺好用"，而是：他们查的第一个词是什么？跟读了吗？评测说的对不对？第二天还会打开吗？

成本：0。这一波的产出决定后面做不做。

### 2. "20 个职场常错词" 内容包（第二波主推）

`docs/发音测试词表.md` 里那 20 个词（preference、comparable、procurement、colleague、hierarchy、iterate……）本身就是极好的传播物：

- **做成一张图**：20 个词 + "你能读对几个？"。这张图在微信群里会被自然转发，因为每个人都想试。
- **落地页就是产品本身**：扫码/点进来第一个词已经填好了，直接看到卡片和跟读。
- **衍生**：拆成 20 条短内容，每条讲一个词（"90% 的人把 colleague 的重音放错了"）。一个词一条，够发一个月。

这个内容包的关键优势：它不需要解释产品是什么。用户读错的那一刻，产品的价值自己就讲清楚了。

成本：设计一张图 + 20 条短文案。

### 3. 垂直社群 + KOC（第二波）

外贸、跨境、出海、售前的微信群和知识星球。进群不硬发，用第 2 项的内容切入。

小红书 / 即刻找 5–10 个中小 KOC（不是大 V），画像是"在外企工作的女生/男生分享职场干货"这类。**这个产品的 demo 天然适合口播视频**：镜头里读一遍 → 屏幕上跳出"重音放错了" → 再读一遍 → "读对了"。15 秒讲完，不需要任何解说。

成本：中小 KOC 单条几百到几千，建议先测 3 条再决定放量。

### 4. 公司内部场景（第二波，很值得试）

外企和出海公司的 HR、销售培训、英语角——**一次触达一群同画像用户**，而且是在"要开口说英文"的具体情境里。可以做成培训环节里的一个小活动（现场读那 20 个词）。

成本：0，靠人脉。转化质量可能比所有线上渠道都高。

### 5. 暂时不要做的

- **投信息流 / SEM**：没有账号体系、没有留存机制、没有任何统计埋点，钱花出去你不知道发生了什么，也留不住人。
- **应用商店 / 小程序**：小程序要注册主体走审核，PRD 里放在产品化阶段。现在别开这个工。
- **做公众号、做内容矩阵**：养号周期长，产品还没验证，不值得。

## 六、开始推之前必须解决的（硬门槛）

完整清单和技术细节在 `试点前置清单.md`，这里只列 marketing 必须知道的四条。**这四条不解决，推广动作就不要启动。**

1. **微信里可能录不了音。** 产品最核心的"跟读"功能依赖浏览器的麦克风权限，而微信内置浏览器对这个权限限制很严。推广靠微信分享，链接大概率在微信里被打开——如果录音失效，用户看到的是一个"读不了"的残缺产品。**必须先实机测一遍**（iPhone 微信、安卓微信各测），然后做好"请在浏览器中打开"的引导。
2. **花钱的接口没有任何防护。** 现在任何人拿到链接，都能无限次调用大模型、语音合成和发音评测，每一次都在花钱。推广一旦带来量（或者被人恶意刷），可能直接把腾讯云额度和账单打爆。**限流必须先加上。**
3. **核心卖点还没验证。** 那 20 个词的实测（能准确指出问题的 ≥ 16 个）是当初定的验收线，还没量过。如果实际只有 10 个准，那第一波 20 个用户会同时发现这件事。**先测，再推。**
4. **公开推广可能需要生成式 AI 服务备案。** 产品用大模型生成内容，面向公众提供服务时，除已有的 ICP 备案外可能还需要在属地网信办做生成式 AI 应用登记。**这件事要在"公开推广"之前确认清楚**，定向邀请朋友试用的阶段风险低，公开投放阶段不能含糊。（这是提醒，不是法律意见，需要正式确认。）

## 七、指标

### 现在能测的

坦白说：**基本没有。** 产品没有任何统计埋点，也没有数据库。现在能拿到的只有服务器日志和腾讯云三个服务的调用量——能看出"有人在用、用了多少次"，看不出多少人来了、有多少人查完就走、有多少人跟读了。

所以第一波 20 人靠**人工问**：每个人聊 5 分钟，比任何报表都有用。

### 第二波之前需要埋的（技术侧）

| 指标 | 为什么要它 |
| --- | --- |
| 打开首页人数 / 完成一次查词人数 | 转化第一关：来了的人有多少真的用了 |
| 查词后点了跟读的比例 | PRD 定的指标（目标 ≥ 50%），衡量"读对"这步是否真被用起来 |
| 出卡片耗时分布 | PRD 定的 ≤ 10 秒，慢了转化必掉 |
| 评测失败率及原因分布 | 太吵、太短还是服务报错，决定要不要改引导 |
| 次日 / 7 日回访率 | 唯一能说明"是不是真需求"的指标 |
| 每次查词的实际成本 | 决定推广量级的天花板 |

### 每一波的通过条件

| 波次 | 规模 | 通过条件（达到才进下一波） |
| --- | --- | --- |
| 第一波 定向邀请 | 20 人 | ≥ 10 人完整走通一次跟读；≥ 5 人第二天自己又打开了；评测反馈"说得对"的比例过半 |
| 第二波 小范围 | 200–500 人 | 次日回访 ≥ 20%；跟读率 ≥ 50%；成本可控且有额度告警；无重大投诉 |
| 第三波 公开 | 不限 | 备案确认完成；限流和监控到位；有账号和历史记录（否则留不住人） |

## 八、如果跳过第一波直接大推，会发生什么

说清楚风险，方便你权衡：

- **一次性烧掉口碑。** 这批人是最精准的人（你的人脉、对口社群），也是最难第二次打动的人。如果他们第一次用就遇到"微信里录不了音"或"评测说错了"，没有第二次机会。
- **成本失控且看不见。** 没有限流、没有用量告警，账单是滞后发现的。
- **拿不到有用的反馈。** 200 个人来了又走，没有埋点，你只知道"来了 200 个人"，不知道他们卡在哪。20 个人一对一聊，能问出五个具体问题。
- **合规上把自己放在灰色区域。** 定向邀请和公开推广，在生成式 AI 服务备案这件事上不是一个量级的风险。

反过来说，第一波的成本几乎是零，时间上也就三五天。**先花三天做第一波，是这份方案里最划算的一笔投入。**
