# 微信录音测试清单

对应 Linear IFM-196。**必须真机做，推测不算数。** 全程大约 15 分钟。

## 为什么非测不可

跟读用的是浏览器标准的麦克风接口。微信自带的浏览器对这个接口限制很严，历史上在 iPhone 上基本拿不到麦克风——微信有自己一套录音接口，和标准的不通用。

而推广是靠微信分享的。**如果微信里录不了音，用户看到的就是一个"能查词、读不了"的产品，恰好缺的就是它唯一的差异点。**

更麻烦的是失败时的提示。现在代码里这种情况会显示：

> 浏览器没给麦克风权限。在网址栏左边的图标里打开它。

微信里**根本没有网址栏**。用户照着找不到，只会以为是自己手机坏了。所以不管测出来能不能录，这句文案都得改。

---

## 准备（2 分钟）

1. 把这个地址发到微信的「文件传输助手」：`https://oncue.imalltrix.com`
   （发给自己就行，不用找别人）
2. **先确认微信本身有麦克风权限**——这一步别跳过，否则测出来的失败分不清是微信浏览器的限制还是系统没授权：
   - iPhone：设置 → 隐私与安全性 → 麦克风 → 确认「微信」是打开的
   - 安卓：设置 → 应用 → 微信 → 权限 → 麦克风，选「仅在使用中允许」或「允许」
3. 记一下版本号，不同版本行为可能不一样：
   - 微信版本：微信 →「我」→ 设置 → 关于微信
   - 手机系统版本：设置 → 通用 → 关于本机（安卓在「关于手机」）

---

## 第一步：对照组（先做这个）

**目的**：先证明你的手机和网站本身没问题。跳过这步的话，微信里失败了你分不清是谁的锅。

1. 用 **Safari**（安卓用 **Chrome** 或自带浏览器）直接打开 `https://oncue.imalltrix.com`
2. 随便查一个词，比如 `schedule`
3. **按住麦克风按钮**读一遍这个词，松手
4. 记录：有没有弹出授权询问？松手后有没有出现评测结果？

> 这一步必须成功。如果这里就失败了，先别测微信，把现象告诉我。

---

## 第二步：iPhone 微信

1. 在微信里点开刚才发给自己的链接
2. 查同一个词 `schedule`
3. **按住麦克风按钮**，读一遍，松手
4. 仔细记录**三件事**：
   - 有没有弹出"允许使用麦克风"之类的询问？
   - 按住的时候，按钮有没有变化（有没有进入"正在录"的状态）？
   - 松手之后屏幕上出现了什么字？**把那句话一字不差地记下来或截图**

常见的三种结果，记的时候对号入座：

| 结果 | 表现 |
| --- | --- |
| A 能用 | 弹授权 → 允许 → 能录 → 出评测结果 |
| B 静默失败 | 按住没反应，或者一按就跳出"浏览器没给麦克风权限"那句话 |
| C 卡住 | 按住像是在录，松手后一直转圈或者没反应 |

---

## 第三步：安卓微信

和第二步一模一样，换台安卓手机再走一遍。安卓微信和 iPhone 微信用的内核不同，**结果很可能不一样，两个都要测**。

没有安卓手机的话，找个同事借五分钟，或者先只报 iPhone 的结果。

---

## 第四步：退路管不管用

不管第二步结果如何，这一步都要测——这是万一微信里用不了时唯一的出路。

1. 还是在微信里打开的那个页面
2. 点**右上角的 ⋯**
3. 找「在浏览器打开」（iPhone 上可能叫「在 Safari 中打开」）
4. 在跳出来的浏览器里再试一次跟读
5. 记录：这条路走得通吗？中间有几步？跳出去之后还是原来那个词的页面吗，还是回到首页了？

## 测完之后我会做什么

- **如果微信里能用**：皆大欢喜，只改那句错误文案（"网址栏左边的图标"在手机上本来就找不到）。
- **如果微信里用不了**（大概率）：
  1. 检测到在微信里打开时，**在用户按麦克风之前**就把话说在前面，而不是等他按了才报错
  2. 配一张图指出右上角 ⋯ 的位置，一步到位
  3. 把结论同步给 marketing —— `docs/GTM.md` 第三节已经留了位置，所有分享链接的文案都要带这句引导
  4. 如果连"在浏览器打开"都很别扭，那就得认真考虑微信小程序了（PRD 里原本放在产品化阶段）

顺带一提，这一轮测出来的东西正好能用：**"微信里为什么录不了音"本身就是一条不错的内容素材**，目标人群天天在微信里点链接，对这件事有共鸣。
