## 二、核心安全原则：只增不改

整个部署过程**不修改任何一个现有文件**，只新增：

- 新增 `/etc/nginx/sites-available/oncue` 和它的软链接
- 新增 `/srv/oncue/` 目录树
- 新增 `/etc/systemd/system/oncue.service`
- 新增 `/etc/oncue/oncue.env`
- 新增系统用户 `oncue`

现有的四个站点配置文件、`/srv/demos`、`/srv/readcore`、`/srv/flash-projects` 一个字节都不碰。

**这条性质决定了回滚很干净**：删掉新增的东西，服务器就回到今天的状态。

## 三、代码怎么上服务器

**本地构建 → 打包 → 上传 COS → 服务器下载**，不在服务器上构建。

理由：

- Next.js 的 `output: 'standalone'` 产物压缩后 **16MB**，只含真正用到的依赖
- 服务器不用装 428MB 的 `node_modules`，不用跑构建，省内存也省时间
- **不走 GitHub**：国内服务器拉 GitHub 不稳定
- COS 桶 `oncue-audio-1257315032` 和服务器同在上海，走内网，快且不计外网流量

传输用**预签名 URL**（本地用 oncue-app 密钥生成，有效期 1 小时），服务器 `curl` 下载即可，这一步不需要在服务器上放任何密钥。

> 说明：构建产物会放在音频桶的 `deploy/` 前缀下。理想情况该单独建桶，但 `oncue-app`
> 没有建桶权限，也没必要为此放宽。用前缀区分即可。

## 四、目录与服务布局

沿用服务器上 readcore 已有的惯例（`/srv/<项目>/current` + `/srv/<项目>/acme`）：

```
/srv/oncue/
├── releases/
│   ├── 20260926-2340/        每次部署一个新目录
│   └── 20260927-1015/
├── current -> releases/...    软链接，切换它即上线或回滚
└── acme/                      certbot 验证用的 webroot
/etc/oncue/oncue.env           环境变量，600，root:oncue
/etc/systemd/system/oncue.service
```

- **运行用户**：新建系统用户 `oncue`，不用 root，也不用 demo-publisher（那是静态发布的身份）
- **监听**：`127.0.0.1:3000`，只听本机，外部只能经 Nginx 进来
- **密钥**：`/etc/oncue/oncue.env` 只放 `oncue-app` 的凭证。
  **绝不把 `imalltrix-ops` 运维凭证放上服务器**——这是配置文档的明确要求

## 五、执行步骤

每一步都通过 TAT 执行，每步之后立即验证，任一步失败就地停下并回滚。

### 第 0 步：部署前基线（只读）

记录现有四个站点的响应，作为"没搞坏"的对照：

```sh
curl -sS -o /dev/null -w '%{http_code} ' https://demo.imalltrix.com/
curl -sS -o /dev/null -w '%{http_code} ' https://readcore.imalltrix.com/
curl -sS -o /dev/null -w '%{http_code} ' https://wish.imalltrix.com/
curl -sS -o /dev/null -w '%{http_code} ' http://118.89.93.225/
nginx -T > /tmp/oncue-nginx-before.conf     # 保存现有配置全文，回滚时对照
```

### 第 1 步：建目录、建用户、放环境变量

```sh
useradd --system --home /srv/oncue --shell /usr/sbin/nologin oncue
mkdir -p /srv/oncue/releases /srv/oncue/acme /etc/oncue
chown -R oncue:oncue /srv/oncue
install -m 600 -o root -g oncue /dev/stdin /etc/oncue/oncue.env <<'EOF'
（内容由单独一次 TAT 写入，不落在本文件里）
EOF
```

验证：`ls -la /srv/oncue`、`stat -c '%U %G %a' /etc/oncue/oncue.env` 应为 `root oncue 600`。

### 第 2 步：上传并解包代码

本地：`npm run build` → `tar` 打包 `standalone + static` → 上传 COS `deploy/oncue-<时间戳>.tgz`。

服务器：

```sh
curl -fsSL "<预签名URL>" -o /tmp/oncue.tgz
mkdir -p /srv/oncue/releases/<时间戳>
tar -xzf /tmp/oncue.tgz -C /srv/oncue/releases/<时间戳>
chown -R oncue:oncue /srv/oncue/releases/<时间戳>
rm -f /tmp/oncue.tgz
ln -sfn /srv/oncue/releases/<时间戳> /srv/oncue/current
```

### 第 3 步：systemd 服务

```ini
[Unit]
Description=OnCue 单词
After=network.target

[Service]
Type=simple
User=oncue
WorkingDirectory=/srv/oncue/current/standalone
EnvironmentFile=/etc/oncue/oncue.env
Environment=NODE_ENV=production PORT=3000 HOSTNAME=127.0.0.1
ExecStart=/usr/bin/node server.js
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/srv/oncue

[Install]
WantedBy=multi-user.target
```

验证（**此时还没碰 Nginx**）：

```sh
systemctl enable --now oncue
systemctl is-active oncue
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/     # 期望 200
```

**这一步如果不通，到此为止，现有站点完全没被影响。**

### 第 4 步：Nginx 先只开 80（为了申请证书）

新增 `/etc/nginx/sites-available/oncue`：

```nginx
server {
    listen 80;
    server_name oncue.imalltrix.com;
    location /.well-known/acme-challenge/ { root /srv/oncue/acme; }
    location / { return 404; }
}
```

```sh
ln -s /etc/nginx/sites-available/oncue /etc/nginx/sites-enabled/oncue
nginx -t                    # 必须通过才继续
systemctl reload nginx
```

验证：现有四个站点再 curl 一遍，状态码和第 0 步一致。

### 第 5 步：申请证书

```sh
certbot certonly --webroot -w /srv/oncue/acme -d oncue.imalltrix.com \
        --non-interactive --agree-tos -m <你的邮箱>
```

和现有三张证书同一套机制（都在 `/etc/letsencrypt/live/`）。
验证：`ls /etc/letsencrypt/live/oncue.imalltrix.com/`、`systemctl is-active certbot.timer`（确认自动续期）。

### 第 6 步：Nginx 开 443 并反代

把 oncue 配置改成完整版（照 readcore 的写法）：

```nginx
server {
    listen 80;
    server_name oncue.imalltrix.com;
    location /.well-known/acme-challenge/ { root /srv/oncue/acme; }
    location / { return 301 https://oncue.imalltrix.com$request_uri; }
}
server {
    listen 443 ssl;
    http2 on;
    server_name oncue.imalltrix.com;

    ssl_certificate     /etc/letsencrypt/live/oncue.imalltrix.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/oncue.imalltrix.com/privkey.pem;

    client_max_body_size 10m;     # 跟读录音上传要用

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;       # 大模型出卡片要几秒
    }
}
```

```sh
nginx -t && systemctl reload nginx
```

## 七、回滚

按影响范围从小到大，出问题时从对应级别开始。

### A 级：应用有问题，站点没问题

```sh
ln -sfn /srv/oncue/releases/<上一个版本> /srv/oncue/current
systemctl restart oncue
```

旧版本目录保留，切软链接即可，几秒完成。

### B 级：OnCue 站点有问题，其它站点要保住

```sh
rm -f /etc/nginx/sites-enabled/oncue
nginx -t && systemctl reload nginx
systemctl disable --now oncue
```

Nginx 回到部署前状态，`oncue.imalltrix.com` 变成无人认领（走 default_server），其它四个站点不受影响。

### C 级：Nginx 整体异常

```sh
diff /tmp/oncue-nginx-before.conf <(nginx -T)   # 先看到底改了什么
rm -f /etc/nginx/sites-enabled/oncue
nginx -t && systemctl reload nginx
```

因为全程**只增不改**，删掉新增的软链接就等于完全还原。

### D 级：彻底清除

```sh
systemctl disable --now oncue
rm -f /etc/systemd/system/oncue.service && systemctl daemon-reload
rm -f /etc/nginx/sites-enabled/oncue /etc/nginx/sites-available/oncue
nginx -t && systemctl reload nginx
rm -rf /srv/oncue /etc/oncue
userdel oncue
certbot delete --cert-name oncue.imalltrix.com     # 证书可留可删
```

## 八、上线前必须先改的一处代码

**跟读评测现在返回的是假结果**（每按一次轮换"读对了/基本对/不对"），那是为了让你看界面。

**上线版本不能这样**——你可能真的以为自己读对了。假的发音反馈比没有反馈更糟。

改法：加一个环境变量开关。本地开发保留假结果方便看界面，
线上显示"跟读评测还没接上，下周做"，等腾讯云口语评测接好再打开。

## 八点五、后来新增的步骤

上线之后加的，不属于首次部署，但更新服务器时要知道它存在。

| 步骤 | 做什么 | 何时执行 |
| --- | --- | --- |
| `steps/05-nginx-limit.sh` | 给 oncue 站点加按 IP 限流（`/result` 60 次/分、`/api/` 240 次/分，突发另算），被限时返回 429 | 一次性；改限流参数时重跑 |

和第 4、6 步一样：只改 `/etc/nginx/sites-available/oncue` 这一个文件，自动备份，`nginx -t` 或任一验证不通过就自动回滚。脚本里会连打 45 次**不带 `?q=` 的** `/result` 来验证限流生效——这种请求应用直接返回"没有收到要查的内容"，不会调大模型，所以验证本身不花钱。

限流只挡"一分钟内太密集"。"一整天慢慢刷"由应用里的每日上限挡（`web/lib/quota.ts`，上限可用环境变量调，见 `web/.env.example`）。

- 不开防火墙改动（80/443 已经通）
